    文档与网页¶

    DarkEye 的文档网页由 MkDocs 和 Material 主题生成。修改 Markdown 源文件后，可以在本地预览，推送到 GitHub 的 main 分支后自动发布。

    1. 文件和网页的位置¶

    内容 仓库内的位置 / 地址
    文档源文件 docs/，每个 .md 文件对应一个页面
    当前页面 docs/doc-webpage.md
    网站名称、导航、主题配置 mkdocs.yml
    Python 文档依赖 requirements-docs.txt
    自动构建和发布流程 .github/workflows/docs.yml
    本地构建产物 site/，已被 Git 忽略，无需提交
    在线文档首页 https://gty5678.github.io/darkeye/
    当前页面的发布地址 https://gty5678.github.io/darkeye/doc-webpage/
    发布任务记录 GitHub Actions：Deploy documentation

    以下命令都在仓库根目录执行，也就是包含 mkdocs.yml 的目录。

    2. 安装文档环境¶

    需要 Python 和 Git。仓库的自动发布环境使用 Python 3.13，本地也建议使用该版本。文档构建不需要安装 Qt 或编译 C++ 程序。

    推荐将虚拟环境放在用户目录，避免把环境文件提交到仓库。

    macOS / Linux¶

    python3 -m venv ~/.venvs/darkeye-docs
source ~/.venvs/darkeye-docs/bin/activate
python -m pip install -r requirements-docs.txt

    Windows PowerShell¶

    py -3.13 -m venv "$HOME\.venvs\darkeye-docs"
& "$HOME\.venvs\darkeye-docs\Scripts\python.exe" -m pip install -r requirements-docs.txt

    后面的命令使用 python。macOS / Linux 每次打开新终端后，需要先执行上面的 source 命令激活环境；Windows PowerShell 可以将 python 替换为 & "$HOME\.venvs\darkeye-docs\Scripts\python.exe"，无需激活。

    3. 修改、预览和构建¶

    修改 docs/ 中对应的 Markdown 文件。新增页面时，还要在 mkdocs.yml 的 nav 中加入入口，例如：

    nav:
  - 文档与网页: doc-webpage.md

    这里的路径相对于 docs/，不要再加 docs/ 前缀；冒号后需要保留空格。以上只是新增导航项的示例，实际修改时保留其他已有导航项。

    启动本地预览：

    python -m mkdocs serve

    浏览器打开 http://127.0.0.1:8000/。保存 Markdown 或配置后，预览会自动刷新；在终端按 Ctrl+C 停止。

    提交前执行与自动发布相同的严格构建检查：

    python -m mkdocs build --strict

    构建成功后，静态网页位于 site/。若检查报错，先根据终端提示修复配置、链接或缺失文件，再推送。

    4. 推送和发布¶

    先确认当前分支与改动范围：

    git branch --show-current
git status --short
git diff -- docs/doc-webpage.md mkdocs.yml

    以提交本页及导航修改为例：

    git add docs/doc-webpage.md mkdocs.yml
git commit -m "docs: add documentation website guide"
git push origin HEAD

    按实际修改的文件调整 git add 列表。git push origin HEAD 会推送当前分支：如果当前是 main，会触发自动发布；如果在其他分支，需要先通过 Pull Request 合并到 main 才会发布。

    发布流程会依次安装依赖、运行 mkdocs build --strict、上传 site/，最后部署到 GitHub Pages。无需手动提交 site/，也无需运行 mkdocs gh-deploy。

    推送后，进入 Deploy documentation 查看对应提交的任务。构建和部署均成功后，再打开在线文档检查内容；如浏览器仍显示旧内容，可尝试强制刷新。

    仓库首次配置发布时，需要在 GitHub 仓库的 Settings → Pages → Build and deployment → Source 中选择 GitHub Actions。仓库也支持在上述 Actions 工作流页面通过 Run workflow 手动触发发布，正式发布应选择 main。

    5. 常见问题¶

    • 提示找不到 mkdocs 模块：确认正在使用文档虚拟环境中的 Python，并重新执行 python -m pip install -r requirements-docs.txt。
    • 本地端口被占用：使用 python -m mkdocs serve -a 127.0.0.1:8001，然后访问 http://127.0.0.1:8001/。
    • 页面没有出现在导航中：检查 mkdocs.yml 的 nav 是否包含该文件，路径和大小写是否正确。
    • 推送后没有发布任务：确认提交已经进入 main，该工作流的自动触发分支只有 main。
    • 发布失败：打开 Actions 中失败的步骤查看日志。若严格构建失败，在本地执行同一命令复现并修复；若部署失败，再检查 Pages 设置和工作流权限。
