# 安全策略（Security Policy）

本项目 **DarkEye** 是一款本地运行的影片元数据管理与分析软件，强调隐私与本地控制。本文件说明本项目的数据存放位置、安全考虑，以及如何报告安全问题。

## 数据存储与目录结构
### 1.1.2之前
- 公共数据存放在 `resources/public` 目录，包括但不限于：
  - `public.db`
  - `workcovers/`
  - `actressimages/`
  - `actorimages/`
- 私有数据（如更敏感的用户自定义信息）存放在 `resources/private` 目录。
- 日志 `log`
- 配置文件`settings.ini`
请根据实际需要妥善备份与保护上述目录，避免将这些目录直接暴露到公共共享盘或未经授权的同步服务中。

### 1.1.2-1.2.4
- 公共数据存放在 `data/public` 目录，包括但不限于：
  - `public.db`
  - `workcovers/`
  - `actressimages/`
  - `actorimages/`
- 私有数据（如更敏感的用户自定义信息）存放在 `data/private` 目录。
`data`文件夹下面还有
- `settings.ini` 设置
- `shortcuts.json`用户自定义快捷键
- `crawler_nav_buttons.json`json驱动的外链，用户可以自行编辑网站

请根据实际需要妥善备份与保护上述目录，避免将这些目录直接暴露到公共共享盘或未经授权的同步服务中。


### 1.2.5及以后
数据仍分为公共库和私有库，主要变化是**程序安装目录与运行数据目录分离**。下文用 `<数据目录>` 表示当前实际使用的数据根目录，它不一定是程序旁名为 `data` 的文件夹。

#### 数据具体放在哪里

打开 **设置 → 常规**，查看页面中的 **数据目录（data-dir）**，即可确认本次运行实际使用的位置。

**标准模式（没有便携标记，也没有显式指定数据目录）**使用系统当前用户的数据目录，由 Qt 的 `AppLocalDataLocation` 确定。当前组织名和应用名均为 `Darkeye`，通常位置如下：

| 系统 | 默认数据目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Darkeye\Darkeye` |
| macOS | `~/Library/Application Support/Darkeye/Darkeye` |

这些目录属于当前系统用户，移动程序文件不会改变数据的位置。

**便携模式**由 `portable.ini` 指定数据目录，官方便携包的布局为：

| 系统 | 便携标记位置 | 标记中的配置 | 实际数据位置 |
| --- | --- | --- | --- |
| Windows | `DarkEye/app-<版本>/portable.ini` | `DataDirectory=../data` | `DarkEye/data/` |
| macOS | `DarkEye/portable.ini`，与 `Darkeye.app` 同级 | `DataDirectory=data` | `DarkEye/data/` |

配置写在 `[Portable]` 分组中。相对路径以 **`portable.ini` 所在目录**为基准，不以启动时的工作目录为基准。macOS 的数据位于 `.app` 外；便携包需要放在可写目录中运行。

高级用法可以通过 `--data-dir` 指定另一套数据目录。完整优先级是：**`--data-dir` → `DARKEYE_DATA_DIR` 环境变量 → `portable.ini` → 系统用户数据目录**。命令行相对路径以启动时的工作目录为基准，环境变量相对路径以程序可执行文件所在目录为基准。切换目录意味着使用另一套数据，不会自动把原目录内容搬过去；便携配置损坏或数据目录不可写时会报错，不会静默切换到其他数据库。

#### 数据怎么存

默认目录结构如下；部分文件在使用相应功能后才生成，数据库、图片和备份位置也可以通过路径配置单独修改：

```text
<数据目录>/
├── public/
│   ├── public.db                  # 公共 SQLite 数据库
│   ├── workcovers/                # 作品封面
│   ├── fanart/                    # 作品剧照
│   ├── actressimages/             # 女优图片
│   ├── actorimages/               # 男优图片
│   └── public_backup/             # 公共库备份
├── private/
│   ├── private.db                 # 私有 SQLite 数据库
│   └── private_backup/            # 私有库备份
├── settings.ini                   # 用户设置及路径配置
├── shortcuts.json                 # 自定义快捷键
├── crawler_nav_buttons.json       # 作品外链配置
├── actress_nav_buttons.json       # 女优外链配置
├── add_work_workspace_layout.json # 添加作品工作区布局
├── logs/darkeye.log               # 运行日志
├── cache/                        # 图片、图谱、翻译等缓存
└── temp/                         # 临时文件
```

- **结构化数据**保存在本地 SQLite 文件中：`public.db` 存作品、人物等元数据，`private.db` 存收藏和个人行为记录等私有信息。“公共库”表示数据分类，不表示对外公开或上传。
- **封面、剧照和人物图片**作为独立文件保存在图片目录中，数据库保存相关记录。仅复制 `.db` 文件不包含这些图片。
- **设置和界面配置**分别使用 INI、JSON 文件保存。
- **私有库并不等于加密库**：当前数据库使用普通 SQLite 存储，INI、JSON、图片和日志也是本地普通文件，不能仅靠目录名称保护隐私。WebDAV 密码由系统凭据存储保存，通常不随便携目录迁移，换机器可能需要重新输入。

#### 旧数据迁移与备份

从 1.1.2–1.2.4 升级时，先退出旧程序并备份旧 `<程序目录>/data/`，再将其**整体复制**到准备使用的新数据目录，确保最终是 `<数据目录>/public/public.db`，不要多套一层 `data/data/`。便携版复制到上表中的 `DarkEye/data/`；标准模式可先从设置中确认实际目录，退出程序后再迁移。已有数据目录应先备份，不要直接混合覆盖。

旧 `settings.ini` 的路径配置会在启动时转换为新的 `Paths/Version=2` 规则：原来的 `data/` 前缀被移除，新相对路径以数据目录为根；绝对路径保持不变。其他旧自定义相对路径会转为基于程序目录的绝对路径，**这一步只调整配置，不移动外部文件**，因此从旧目录搬迁前应检查自定义路径。数据库兼容性以具体版本为准，回退程序前也应备份。

完整备份建议在退出程序后复制整个数据目录，并额外备份路径配置指向的外部数据库和图片目录。SQLite 使用 WAL 模式，运行中可能存在 `.db-wal`、`.db-shm` 文件，不应在程序写入时只复制主 `.db`；也可以使用“设置 → 数据库”中的备份功能生成数据库快照。精简数据库备份不包含图片，也不包含全部设置。

便携版升级时保留 `data/` 和已有 `portable.ini`，只替换程序部分；不要同时运行多个版本访问同一套数据。更多布局与升级说明见[双平台编译与打包](cross-platform-packaging.md)。

## 数据与隐私（Data & Privacy）

- DarkEye 默认在本地运行，不会主动将数据库内容或封面图片等数据上传到开发者控制的服务器。
- 程序运行产生的日志、缓存等文件中，可能包含：
  - 访问的站点 URL
  - 本地文件路径
  - 元数据字段（如作品标题、演员名等）
- 在共享日志或截图前，请自行检查是否包含个人隐私或敏感信息。

## 文件与网络访问

- 程序会读写以下类型的本地资源：
  - 当前数据目录下 `public/` 与 `private/` 中的数据文件与图片，以及路径配置指定的外部位置；
  - 配置文件与缓存目录（如 `settings.ini`、日志文件等）。
- DarkEye 在需要采集数据时，可能会通过本地 FastAPI 接口与浏览器插件通信，并访问外部网站：
  - 此类访问仅用于抓取影片元数据；
  - 请确保你的网络环境与代理配置符合当地法规及站点使用条款。

## 非安全目标与限制（Out of Scope）

以下情况通常不被视为本项目的安全漏洞：

- 用户以管理员 / root 权限运行程序导致的系统破坏；
- 用户修改源码或编写自定义脚本 / 插件引入的任意代码执行风险；
- 用户自行下载的恶意数据文件（含恶意元数据、图片等）；
- 第三方依赖库本身的安全问题（请直接向对应项目报告）。

## 报告安全问题（Reporting a Vulnerability）

如果你认为 DarkEye 存在潜在的安全问题，**请不要在公开 issue 中直接披露细节**。

你可以通过以下方式私下联系我们：

- 邮箱：`security@example.com`（请根据实际情况替换）

在报告时，请尽量包括：

- 使用的操作系统与 DarkEye 版本；
- 复现步骤（最好包含最小复现用例）；
- 预期行为与实际行为；
- 如果可以，提供 PoC（Proof of Concept）代码或脚本。

我们会尽力在合理时间内回复并评估问题，必要时发布修复版本，并在得到你许可的前提下在变更日志中致谢。
