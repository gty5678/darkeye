    GPU 力导向图第二轮性能优化¶

    顺序与实现¶

    1. 计时：CPU 命令记录、几何准备、文字准备、读回批次延迟分别统计。GPU 后端原先的 Tick 改标为“快照延迟”，显示请求到读回回调的完整延迟，不再把它当作物理单步耗时。D3D11 提供边界、排序、建树、力计算四段 GPU 时间戳，面板按需开启。其他后端显示不可用，不把 CPU 延迟伪装成 GPU 执行时间。查询不阻塞等待结果，开启时间戳会增加 CPU 提交开销。
    2. 排序和聚合：默认采用稳定的四位 radix sort（八轮），重复 Morton 编码保留原节点顺序；每个工作组直接聚合树底部七层。十万节点每步由 191 次 dispatch 降至 48 次。保留旧 bitonic/逐层聚合路径，供数值对照及同机比较。
    3. 计算与快照解耦：读回未完成时仍可继续提交计算，常规快照间隔约 33 ms；拖拽优先读回。常规队列最多领先已消费快照八步，拖拽时最多两步，避免无限排队。冷却按已提交的物理步推进，近似收敛判定消费最近完成的速度统计；停止时补读最终状态。
    4. 实例化绘制：GPU 从常驻仿真位置生成节点/边实例，顶点着色器展开圆、线段和箭头。CPU 缓存半径、颜色和高亮分组，只在拓扑/样式/高亮变化时更新描述，平移缩放不重新生成全部顶点。保持原先的 dim/highlight/rest 与文字穿插顺序。暂停时上传冻结快照，继续使用实例化路径。
    5. 文字预算：两千节点以上启用屏幕密度限制（80×24 物理像素单元）、六像素最小字号和最多约两千个标签；当前 hover 标签优先保留。文字顶点通过 compute 跟随最新 GPU 节点位置，CPU 低频快照不再造成标签落后。小图保留原有标签展示。

    性能测量方法¶

    环境与首版相同：Ryzen 5 7500F、Quadro P600、Windows/D3D11、Qt 6.12.0、MSVC Release。合成图使用种子 42、N−1 条链式边，位置范围为 ±(25√N+50)。

    物理计算比较保留旧路径和新路径，每轮重新初始化并预热，五轮测量取中位数。时间含 CPU 命令记录、GPU 执行与状态读回；关闭阶段时间戳后测总时间，再额外采集阶段样本。阶段样本不是五轮中位数，且包含 GPU 时间线中阶段间的空档。

    绘制准备比较使用静止位置、十万节点、相同视口，关闭力但持续请求绘制，跳过首次准备后取最近样本中位数。该指标只衡量 CPU 几何准备，不含 GPU 绘制时间，不能按该比值宣称 FPS 提升。

    最近结果¶

    十万节点指标 旧路径 新路径
    物理单步 dispatch 数 191 48
    物理单步总时间 17.93 ms 16.61 ms
    CPU 几何准备（缓存命中） 7.54 ms/帧 0.011 ms/帧

    阶段样本中，新路径排序约 4.33 ms、力计算约 9.27 ms。减少提交次数后，力遍历与访存仍占主要成本。更高 GPU 利用率或更低 CPU 准备时间不能直接换算为整页 FPS；图的分布、边数、可见内容和设备都会影响结果。

    验证和复现¶

    • 新旧计算路径逐点对照覆盖 1、127、128、129、256、257、10000、100000 节点，检查工作组边界、补齐和 Morton 重复键。
    • 验证快照未消费时继续计算，旧快照保持原版本、最终快照对应最新 GPU 状态。
    • 实例化图像与 CPU 绘制逐像素比较，并测试运行时修改节点颜色；文字顶点读回核对最新 GPU 锚点位置。
    • 覆盖大图标签预算、长期冷却稳定性、拖拽、暂停恢复、后端切换、图增删、既有物理和页面渲染测试。
    • 性能面板勾选“GPU 阶段计时”可观察 D3D11 最近完成的阶段样本；比较正常性能时关闭该选项。
    • 每个力导向图自带性能悬浮表，通过图内右键菜单“性能表”开关；主界面与演示程序使用同一实现，演示程序默认关闭逐帧日志。
    • 最终 Debug 四组图相关回归全部通过；GPU 套件 28 项通过、3 项可选基准跳过。Release 开启可选基准后 31 项通过、0 失败。主程序和演示程序 Debug 构建通过。
    • 构建与运行命令沿用 迁移计划；设置 DARKEYE_GPU_LAYOUT_BENCHMARK=1 会额外运行计算路径对照和十万节点视图准备基准。详细结果保存在构建目录 tests/gpu-simulation-results.txt。

    空间排序复用、局部布局更新及其他平台的原生 GPU 时间戳没有在这一轮引入；它们需要单独验证布局质量和后端行为。

    文字稳定性修复¶

    先按 CPU 快照对标签原点取整、再叠加 GPU 位移，会使字形在 CPU 快照更新时改变亚像素相位。现改为上传与节点位置无关的局部字形坐标和标签偏移，GPU 使用最终节点位置计算标签原点，并在实际帧缓冲的物理像素空间统一取整。CPU 回退采用同一对齐公式，保留字形内部尺寸和相对位置；高 DPI 下使用实际像素宽高分别计算比例。

    大图密度选择优先保留已经显示且仍可见的标签，避免节点跨格子时让两个标签反复交替。相机平移、缩放和视口变化时也保留选择；离开带余量视口的标签会释放名额，新候选使用以场景原点锚定的密度格子补入。仅更换图或标签布局时清空选择。

    修复后 Debug 四组图相关回归全部通过；Debug 与 Release 的 GPU 套件均为 28 项通过、3 项可选基准跳过。新增检查内容包括带文字的 CPU/GPU 画面对照、分数缩放与平移下的物理像素对齐、字形尺寸保持。主程序与演示程序已重新构建。

    400 节点显示约 16 ms 的“快照延迟”仍可能来自按帧交付读回回调。它不是 GPU 物理单步时间，也不能与首版 CPU Tick 或预热批次分摊值直接比较。

    运动中的可见性误剔除¶

    后续复现到另一处独立问题：字形位置使用 GPU 最新状态，而 CPU 仍用旧快照判断标签是否在视口内。队列最多领先八步，每步位移限幅 15 世界单位，位置差可以达到 120；原先 50 世界单位的边缘余量不足，会让实际可见文字被提前删除，快照追上后又出现。

    GPU 小图现在保留全部文字候选，由 GPU 栅格裁剪处理；大图的候选范围增加与队列上限、位移限幅一致的保守余量。CPU 后端保持原可见性逻辑。

    2026-10-29 修复大图相机移动造成的标签替换：原逻辑每次平移或缩放都会清空保留集合，并按相对相机的格子重新竞争，导致两个相邻可见标签在格子边界反复出现/消失。2500 节点回归在修复前明确失败；新增 CPU/GPU 双路径覆盖小幅往返平移、微小缩放，以及大幅移动后旧标签退出、新标签补入。标签预算仍限制为 2000 个普通标签并允许当前悬浮标签。

    新增回归把 GPU 节点保留在画面内、CPU 快照设为画面外：修复前标签顶点为空并导致测试失败，修复后标签实际可见。另增加连续 30 帧运动文字的轮廓/明暗/移动方向检查，归一化字形图像差为 0；实际 400 节点 demo 的文字可见缩放下也验证了视口稳定性。Debug 五组图相关回归通过，Debug/Release GPU 套件均为 30 项通过、3 项可选基准跳过。

    图内性能悬浮表¶

    ForceViewRhiWidget 内置独立的 ForcePerformanceOverlay，默认隐藏。图内右键勾选“性能表”后显示在左上角，再次取消勾选或点击表头关闭按钮隐藏。计算后端切换、GPU 阶段计时开关与所有指标都属于当前图，不依赖主界面的设置面板或 demo 侧栏。

    性能表不加入画布布局，显示、隐藏和指标文本变化不会改变视口尺寸或缩放。窗口变小时表格限制在图内并提供滚动条；表内鼠标操作不会传递为图的平移或缩放。指标每 250 ms 刷新可见表格，隐藏时只保存最新数据。

    显示性能表时自动开启 GPU 阶段计时，隐藏、关闭表格或隐藏所在页面/窗口时自动关闭；重新显示会再次开启。表内复选框保留，可在表格显示期间手动关闭计时，观察不含阶段计时开销的性能。自动开关仅影响当前图的计时采样，不改变 GPU/CPU 计算后端。

    Windows 下性能表统一使用已安装的 Microsoft YaHei UI，不再为数值行单独指定 Consolas 等系统等宽字体，减少中英文混排的字体回退。2026-10-29 的原生首次异常堆栈采集复现了打开性能表时 6 次 DirectWrite (DWrite.dll) 内部异常；修复后相同测试为 0 次，D3D11 调试层计时检查也通过。测试使用 DARKEYE_TRACE_OVERLAY_EXCEPTIONS=1 和 tracePerformanceOverlayExceptions 可复查；异常处理器仅观察并继续系统正常处理，不吞掉异常或改变 VS 异常设置。

    原生 Qt/QRhi 回归覆盖右键菜单、关闭与重新显示、两个图的可见性/后端/计时/数据独立、尺寸限制以及鼠标事件隔离，并检查悬浮表截图。Debug 五组图相关回归全部通过，GPU 套件 31 项通过、3 项可选基准跳过；主程序和 demo 已重新构建。

    悬浮高亮在 GPU 上混色¶

    节点、边与箭头的实例描述保存基础颜色和高亮标记，已有的几何计算着色器根据悬浮强度混合颜色，并放大悬浮节点。淡入、淡出期间复用实例描述，只更新 96 字节的几何参数，不再随动画进度遍历全部节点和边、重算颜色并上传整批实例数据。修改高亮色、暗化节点色和暗化边色也只更新参数；没有新增计算 pass、CPU 等待或读回。

    CPU 仍负责鼠标命中、邻居搜索和绘制分组。悬浮目标或邻居深度变化、图结构/基础样式变化、淡入淡出的起止边界会重建分组，以维持暗化文字、高亮边和节点的原有遮挡顺序。文字的标签筛选、排版和颜色准备保持既有路径。

    Release 原生 D3D11，在同一台 Ryzen 7500F / Quadro P600 机器上，固定十万节点、99999 条链式边、关闭物理力与文字，预热后改变悬浮强度，采集 32 帧 prepareGpuGeometry 的 CPU 耗时取中位数：优化前 11.6393 ms，优化后 0.005 ms。首帧分组与实例上传不计入这组动画缓存命中数据；结果不包含 GPU 执行、文字准备或整帧时间，不能据此推算 FPS。

    复现：设置 DARKEYE_GPU_HOVER_BENCHMARK=1，运行 GPU 测试程序的 hoverGeometryPreparationBenchmark。本轮 Debug 五组图相关回归全部通过；Release GPU 套件包含新基准时 33 项通过、3 项其他可选基准跳过。着色器缓冲区读回测试核对混色、透明度、半径与实例缓存，CPU/GPU 画面对照覆盖悬浮淡入淡出、邻居高亮及文字层级。

    GPU 模拟独立于绘制推进¶

    GPU 模拟由 GUI 线程上的定时器提交 QRhi 离屏计算，绘制回调只读取当前 GPU 状态。页面隐藏或窗口最小化后继续计算，收敛并排空最终快照后不再提交计算；暂停、继续、重启和后端切换仍沿用既有生命周期。QRhi 尚未初始化或已有帧正在录制时跳过本次定时器，避免嵌套帧。

    此实现复用画布的 QRhi 设备，不新增计算线程，也不主动调用 finish()。Qt 的 endOffscreenFrame() 在存在读回时会等待 GPU 完成，因此快照提交仍可能占用 GUI 线程时间；不能把独立于绘制等同于完全异步计算。首次 GPU 初始化仍需要画布曾经显示并获得设备。

    回归覆盖隐藏页面、最小化窗口时无绘制仍推进 GPU、后台暂停/继续与收敛、恢复显示，以及停止计算定时器后单独绘制不推进物理步数。

    柔和积分与拖拽速度修复¶

    CPU 和 GPU 使用同一组指数阻尼积分系数，每步仍只计算一次力。设原每步累积的力冲量为 F、速度保留率为 r、步长为 h，速度仍为 v1 = r * (v0 + F)；位置改为按步内恒定驱动力与连续阻尼的解析解推进：

    • w = (1-r) / (-log(r))
    • dx = h*w*v0 + h*r/(1-r)*(1-w)*F

    这保持原有恒力终端速度，减轻从静止开始或受力突变时的位移。无阻尼极限采用 dx = h*v0 + h*F/2；完全阻尼时不移动。它对步内恒定力的阻尼运动精确，整个非线性受力系统仍每步采样一次力，不保证任意刚性参数下无振荡。

    位移与速度按 1/sqrt(1+(travel/maxDisplacement)^2) 同比平滑限幅；travel 取实际位移长度和末速度乘步长的较大者，维持每步位移上限。收敛统计保留自由节点限幅前速度。拖拽节点固定在目标位置，末速度与收敛贡献均为零，避免释放时带入约束期间累积的速度。

    CPU Barnes–Hut 仅近似不包含当前节点的子树，避免将自身质量计入斥力。回归覆盖解析首次位移、长期收敛、拖拽释放、包含自身的聚合单元，以及 CPU/GPU 多步常驻状态对照。

    2026-11-07：macOS Debug 构建通过；CPU 物理套件通过，真实 Metal GPU 套件 41 项通过、0 失败、6 项平台专属或可选测试跳过。渲染回归等待对应性能统计更新，避免读取初始化阶段的旧统计。

    按完成耗时调度与运动反馈冷却（2026-11-07）¶

    此节替代早期固定 16ms 提交、预热四步/常规单步、八步队列与约 33ms 快照的调度策略。GPU 模拟活跃且未拖拽时用 1ms 精确定时器让出事件循环后继续提交；模拟不依赖绘制回调。画布更新请求仍以约 16ms 节流，收敛时请求最后一帧。隐藏、最小化后继续计算，空闲时定时器恢复 16ms。拖拽维持约 16ms 的单步提交。

    GpuSimulationSchedule 根据已完成批次的记录、读回完成和 CPU 消费耗时估计成本，以约 12ms 为软预算，在 1–32 步之间调整批量。从单步起逐步扩批，对慢样本立即收缩；预算内允许小幅探测扩批，避免驱动固定开销把批次锁在单步。每批复用拓扑与常驻位置，只上传一次控制参数并读回一次结果；最多一个批次在途，避免 GUI 被无界 GPU 队列拖住。重启和参数变化重新学习成本，不再关闭批量加速。实例和标签的保守 CPU 可见性余量按最大 32 步的位移差扩大。

    这个预算包含提交与同步开销，不是 GPU 硬件时间戳；原生阶段计时仍仅在支持的后端提供。QRhi 仍由 GUI 线程使用，读回提交可能等待 GPU；12ms 是反馈控制目标，不是硬性时限，单步成本较高或驱动抖动时会超出。更大的 uniform 缓冲覆盖 32 步的完整排序/建树 passes，reference bitonic 和 optimized radix 路径均验证了最大批次。

    冷却改为观察自由节点的平均速度、峰值速度和运动衰减趋势：启动前 32 步保留热度；运动正在自然衰减时保留当前热度，停滞或振荡阶段渐进冷却，安静时更快降温。到达最低热度后继续模拟，不再仅按 alpha 阈值冻结。低热度下，平均速度低于 0.01、峰值低于 0.1，累计至少 32 步且至少三个独立观测均安静才停止，避免大图中的少数移动节点被平均掉。GPU 每批末反馈一次，CPU 每步反馈一次，二者采用同一规则但冷却轨迹不要求逐步相同。暂停后即使已经达到最低热度也可恢复；重启清空运动历史。

    性能表新增模拟步/批次、已提交模拟步和估计完成耗时/步，绘制帧率仍独立显示。收敛、初始化切换绘制路径时立即更新统计，避免快速结束后留下初始化阶段的旧数据。

    真实 Metal（Apple M6）、Debug，同一应用尺度合成图，128 个相同物理步、相同 alpha，比较固定四步/16ms 与自适应调度，含提交和读回、不含整页绘制：

    节点数 固定四步/16ms 自适应调度 本次最大批次
